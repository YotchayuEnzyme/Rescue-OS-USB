# 📌 บันทึกความคืบหน้าโปรเจกต์: Rescue-OS (Rescue-Drive.sh)

---

## 1. เป้าหมายและสภาพแวดล้อมระบบ (System Architecture)

**ระบบปฏิบัติการ (Operating System)**

- Alpine Linux 3.24.2 (x86_64)
- ทำงานในโหมด Diskless โดยโหลดระบบขึ้นมารันบน RAM
- เก็บค่าคอนฟิกถาวรด้วย `lbu commit`

**โครงสร้างโปรแกรม (Program Architecture)**

- ภาษา: POSIX Shell (`#!/bin/sh` สำหรับ BusyBox ash)
- GUI: Zenity
- File Manager: Thunar

**หัวใจสำคัญ (Core Concept)**

พัฒนาระบบกู้และดึงข้อมูลจากฮาร์ดดิสก์ที่มีปัญหา ทั้ง Windows และ Linux โดยยึดหลัก **Forensic-grade Read-Only (Zero-Write)**

> ห้ามมีการเขียนข้อมูลทับลงดิสก์ต้นฉบับโดยเด็ดขาด

---

## 2. ไทม์ไลน์การพัฒนา (Development Phases)

### Phase 1: วางโครงสร้างพื้นฐานและระบบจำแนกไดรฟ์อัตโนมัติ (Heuristic Role Detection)

**ปัญหาเริ่มต้น**

บน Linux ไม่มีตัวอักษรไดรฟ์อย่าง `C:` หรือ `D:` และหากพาร์ทิชันของลูกค้าไม่ได้ตั้งชื่อป้าย (LABEL) ไว้ ผู้ใช้งานทั่วไป (End User) จะแยกไม่ออกว่าพาร์ทิชันใดเป็นไดรฟ์ติดตั้ง Windows หรือไดรฟ์เก็บข้อมูล

**สิ่งที่พัฒนา**

- สร้างระบบเมาท์ชั่วคราวเพื่อสำรวจโครงสร้างโฟลเดอร์ภายใน โดยใช้ `/tmp/rescue_probe`
- ตรวจหาโฟลเดอร์สำคัญ เช่น `Windows/System32`, `Users`, `EFI` และ `etc/usr`
- แปลผลเป็นภาษาที่ผู้ใช้ทั่วไปเข้าใจง่าย เช่น
  - 🪟 **ระบบ Windows (Drive C:)**
  - 📁 **ไดรฟ์ข้อมูลทั่วไป (Data/D:)**
- ดึงค่าพื้นที่ใช้งานจริง (USED) มาแสดงในตารางคู่กับขนาดรวม (SIZE)

---

### Phase 2: ยกระดับความปลอดภัยระดับ Kernel และ Refactor โค้ด (Forensic Safety)

**ปัญหาเดิม**

- โค้ดชุดแรกเขียนรวมกันอยู่ใน `case` เดียว ทำให้ดูแลและแก้ไขยาก
- ตัดดิสก์ระบบด้วยการตรวจสอบชื่ออุปกรณ์ `sda` แบบตายตัว
- เผลอเรียก `ntfsfix -d` อัตโนมัติ ซึ่งมีการเขียนข้อมูลลงดิสก์
- ต่อสตริงรายชื่อพาร์ทิชันแบบธรรมดา ทำให้เกิดปัญหาเมื่อ LABEL มีช่องว่าง

**สิ่งที่พัฒนา**

**1. Dynamic System Disk Detection (`get_sys_disks`)**

ตรวจสอบดิสก์ที่ระบบ Rescue-OS ใช้งานเองจาก `/etc/lbu/lbu.conf` และจุดเมาท์ `/media/*` เพื่อซ่อนดิสก์ระบบออกจากตารางโดยอัตโนมัติ ไม่ว่าจะเสียบอยู่ช่องใดหรือได้รับชื่ออุปกรณ์อะไร

**2. Strict Read-Only (`mount_ro`)**

กำหนดแฟล็กเพื่อป้องกันการเขียนข้อมูลลงดิสก์ต้นฉบับ รวมถึงการ Replay Journal โดยใช้แฟล็กตามประเภทระบบไฟล์ ได้แก่

- NTFS: `norecover`
- ext3/ext4: `noload`
- XFS: `norecovery`

หลังเมาท์จะตรวจสอบ `/proc/mounts` ซ้ำทุกครั้งว่าเป็น Read-Only (`ro`) จริง หากไม่ใช่จะสั่ง `umount` ทันที

**3. User Consent สำหรับ `ntfsfix`**

หาก NTFS มีสถานะ Dirty/Fast Startup จนเมาท์แบบ Read-Only ไม่ผ่าน ระบบจะแสดงหน้าต่างถามผู้ใช้ก่อนเสมอว่าจะยอมให้ใช้ `ntfsfix -d` หรือไม่

**4. รองรับ LABEL ที่มีช่องว่าง**

เปลี่ยนวิธีส่งข้อมูลเข้าตาราง Zenity โดยใช้ Positional Parameters (`set -- "$@"`) เพื่อป้องกันชื่อป้ายที่มีช่องว่างทำให้ข้อมูลเพี้ยน

**5. Logging**

เพิ่มระบบบันทึกประวัติการทำงานและข้อผิดพลาดลงใน `/tmp/rescue.log`

### Phase 3: รองรับไดรฟ์เข้ารหัส (LUKS / BitLocker) และระบบถอดไดรฟ์ (Safe Eject)

**สิ่งที่พัฒนาในรอบแรก**

- เพิ่มการปลดล็อก `crypto_LUKS` ด้วย `cryptsetup`
- เพิ่มการปลดล็อก BitLocker ด้วย `dislocker` ซึ่งใช้ FUSE และ Loop
- เพิ่มเมนูที่ 6 (Safe Eject) สำหรับปลดเมาท์และล็อกไดรฟ์กลับ

**ปัญหาที่พบจาก `dislocker`**

- แพ็กเกจอยู่ในคลัง `testing` ของ Alpine จึงมีข้อกังวลด้านความเสถียร
- ต้องพึ่งพาทั้ง FUSE และ Loop ซ้อนกัน 2 ชั้น
- การส่งรหัสผ่านผ่าน Argument อาจทำให้รหัสผ่านปรากฏใน Process Table ชั่วขณะ

**การ Refactor ระบบเข้ารหัส**

เปลี่ยนมาใช้ `cryptsetup` เป็นศูนย์กลางผ่านฟังก์ชัน `unlock_encrypted`

- ใช้ `cryptsetup open --readonly --type bitlk` สำหรับ BitLocker
- ใช้ `cryptsetup open --readonly --type luks` สำหรับ LUKS
- ส่งรหัสผ่านหรือ Recovery Key 48 หลักผ่าน Standard Input ด้วย `--key-file=-`
- ลดความเสี่ยงที่รหัสผ่านจะปรากฏใน Process Table
- ไม่จำเป็นต้องใช้ `dislocker` อีกต่อไป

### Phase 4: เก็บรายละเอียดการใช้งานจริง (Edge Cases & Polish — ล่าสุด)

**1. แสดงสถานะไดรฟ์เข้ารหัสหลังปลดล็อก**

ปรับปรุง `select_partition` ให้ตรวจสอบว่าพาร์ทิชัน LUKS/BitLocker ถูกปลดล็อกไว้ที่ `/dev/mapper/rescue_<part>` แล้วหรือไม่

หากปลดล็อกแล้ว ระบบจะสำรวจโฟลเดอร์และพื้นที่ภายใน พร้อมแสดงประเภทไดรฟ์ เช่น

- 🔓 🪟 **ระบบ Windows**
- 🔓 📁 **ไดรฟ์ข้อมูลทั่วไป**

แทนที่จะแสดงข้อความ “กดเพื่อปลดล็อก” ซ้ำ ๆ

**2. กรอง Signature ที่ตกค้างบริเวณหัวดิสก์**

ป้องกันไม่ให้ระดับ Disk ซึ่งมีพาร์ทิชันย่อยอยู่แล้วแสดงซ้ำซ้อนในตาราง แต่ยังรองรับแฟลชไดรฟ์แบบ Superfloppy ที่ไม่มีตารางพาร์ทิชันได้ตามปกติ

**3. ทดสอบจริงบน VirtualBox**

จำลองและทดสอบดิสก์ประเภทต่าง ๆ ได้แก่

- NTFS (Windows)
- ext4 (Data)
- LUKS (Encrypted Disk)

พร้อมฝึกวิเคราะห์โครงสร้างอุปกรณ์จัดเก็บข้อมูลด้วย `lsblk -f`

## 3. สถานะปัจจุบันของแต่ละเมนู (Current Status)

| เมนู | ฟีเจอร์ | สถานะ |
|---|---|---|
| 1 | Safe Mount | ✅ เสร็จสมบูรณ์ |
| 2 | S.M.A.R.T. Check | 🟡 ทำงานได้ขั้นพื้นฐาน |
| 3 | Offline Antivirus | ⚪ Placeholder |
| 4 | โหมดผู้เชี่ยวชาญ | ✅ เสร็จสมบูรณ์ |
| 5 | Shutdown | ✅ เสร็จสมบูรณ์ |
| 6 | Safe Eject | ✅ เสร็จสมบูรณ์ |

### รายละเอียดแต่ละเมนู

**เมนู 1 — Safe Mount**

- จำแนกประเภทไดรฟ์อัตโนมัติ
- รองรับ LUKS/BitLocker ผ่าน `cryptsetup`
- บังคับเมาท์แบบ Read-Only ตามแนวทางที่กำหนด

**เมนู 2 — S.M.A.R.T. Check**

- ใช้ `smartctl -H` ตรวจสอบดิสก์ลูกแรก
- ยังรออัปเกรดให้เลือกดิสก์ได้ และสรุปค่าสำคัญให้อ่านง่าย

**เมนู 3 — Offline Antivirus**

- ปัจจุบันยังเป็นหน้าต่างข้อความ Placeholder
- รอเชื่อมต่อ ClamAV

**เมนู 4 — โหมดผู้เชี่ยวชาญ**

- ออกจากสคริปต์เข้าสู่ Desktop/Terminal

**เมนู 5 — Shutdown**

- ปิดระบบด้วย `poweroff`

**เมนู 6 — Safe Eject**

- ไล่ `umount` ทุกพาร์ทิชันที่เกี่ยวข้อง
- สั่ง `cryptsetup close` สำหรับ Mapper ทั้งหมดอย่างปลอดภัย

## 4. แผนงานถัดไป (Next Steps / Backlog)

### 4.1 ทดสอบ BitLocker กับไฟล์ VHD จริง

เป้าหมาย:

- ทดสอบการปลดล็อกด้วยรหัสผ่าน
- ทดสอบการปลดล็อกด้วย Recovery Key 48 หลัก
- ตรวจสอบการทำงานของ `cryptsetup --type bitlk`

### 4.2 อัปเกรดเมนู 2 — Advanced S.M.A.R.T. Check

พัฒนาระบบตรวจสอบสุขภาพดิสก์ให้เลือกฮาร์ดดิสก์ลูกที่ต้องการตรวจได้ พร้อมสรุปข้อมูลสำคัญ ได้แก่

- อุณหภูมิ (Temperature)
- ชั่วโมงการทำงาน (Power-On Hours)
- จำนวน Bad Sectors
- จำนวน Reallocated Sectors

นำข้อมูลมาแสดงในตารางที่ผู้ใช้ทั่วไปสามารถอ่านและเข้าใจได้ง่าย

### 4.3 เพิ่มฟีเจอร์ Quick Backup

พัฒนาระบบคัดลอกโฟลเดอร์สำคัญของลูกค้าไปยังไดรฟ์ปลายทางด้วย `rsync`

โฟลเดอร์เป้าหมายเบื้องต้น:

- Desktop
- Documents
- Pictures

ความสามารถที่ต้องการ:

- แสดง Progress Bar ระหว่างคัดลอก
- ตรวจสอบพื้นที่ว่างของไดรฟ์ปลายทางล่วงหน้า
- แสดงผลการคัดลอกและข้อผิดพลาดให้ผู้ใช้เข้าใจได้ง่าย

### 4.4 อัปเกรดเมนู 3 — Offline Antivirus

เชื่อมต่อระบบสแกนไวรัสแบบออฟไลน์เข้ากับ ClamAV เพื่อให้สามารถตรวจสอบไฟล์ในไดรฟ์ที่นำมาตรวจได้โดยไม่ต้องบูตเข้าสู่ระบบปฏิบัติการต้นฉบับ

---

## 5. สรุปภาพรวมโปรเจกต์ (Project Overview)

Rescue-OS เป็นระบบช่วยกู้และดึงข้อมูลจากฮาร์ดดิสก์ที่มีปัญหา โดยเน้นความปลอดภัยของข้อมูลต้นฉบับเป็นอันดับแรก

ปัจจุบันระบบมีโครงสร้างหลักสำหรับตรวจจับ จำแนก เมาท์ และปลดล็อกไดรฟ์ รวมถึงระบบ Safe Eject แล้ว ส่วนงานที่กำลังจะพัฒนาต่อคือการตรวจสุขภาพฮาร์ดดิสก์ การสำรองข้อมูล และการสแกนไวรัสแบบออฟไลน์

**หลักการสำคัญที่สุดของโปรเจกต์:** การป้องกันการเขียนข้อมูลลงดิสก์ต้นฉบับต้องมาก่อนความสะดวกในการใช้งานทุกครั้ง
