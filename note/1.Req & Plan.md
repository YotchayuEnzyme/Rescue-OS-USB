#### **1. Requirement \& Planning (เป้าหมายและขอบเขตของโปรเจกต์)**

##### Objective (วัตถุประสงค์หลัก):

###### สร้างแฟลชไดรฟ์ระบบปฏิบัติการฉุกเฉิน (Live USB Rescue-OS) ที่มีขนาดกะทัดรัด กินทรัพยากรต่ำ เพื่อใช้เสียบกู้ข้อมูล ซ่อมแซมพาร์ทิชัน และจัดการระบบสำหรับคอมพิวเตอร์ที่ OS หลักเสียหายหรือไม่สามารถบูตได้ โดยตัวระบบจะต้องทำงานบน RAM ของเครื่องเป้าหมาย 100%

###### 

###### Core Features (ฟีเจอร์หลักที่ต้องมี):

###### 

###### Lightweight Core: ใช้ Alpine Linux เป็นแกนหลัก เนื่องจากมีขนาดเล็ก บูตไว และออกแบบมารองรับการรันบน RAM (Live Mode) ได้อย่างสมบูรณ์แบบ

###### 

###### User-Friendly GUI: ใช้ XFCE4 เป็นหน้าจอเดสก์ท็อป เพื่อให้มีกราฟิกที่ลื่นไหลแม้ใช้กับคอมพิวเตอร์รุ่นเก่า ช่วยให้ผู้ใช้ลากวางไฟล์เพื่อกู้ข้อมูลได้สะดวกโดยไม่ต้องใช้ Command Line ตลอดเวลา

###### 

###### Disk \& Partition Tools: ติดตั้งโปรแกรม GParted และเครื่องมือตรวจสอบดิสก์พื้นฐาน (fdisk, lsblk) สำหรับวิเคราะห์และซ่อมแซมโครงสร้างพาร์ทิชัน

###### 

###### Cross-OS File Access: รองรับการเมานต์ (Mount) อ่านและเขียนข้อมูลบนฮาร์ดดิสก์รูปแบบของ Windows (NTFS, FAT32, exFAT) เพื่อดึงไฟล์สำคัญออกมาได้อย่างปลอดภัย

###### 

###### Remote Management (Dev Mode): เปิดใช้งาน SSH Port เพื่อความสะดวกในการใช้คอมพิวเตอร์อีกเครื่องรีโมตเข้ามาทดสอบระบบและเขียนสคริปต์ระหว่างการพัฒนา

###### 

###### System Workflow (แผนผังการทำงานของระบบ):

###### 

###### Boot Phase: เสียบ Live USB เข้ากับเครื่องที่ต้องการกู้ภัย -> ตั้งค่า BIOS/UEFI ให้บูตจาก USB

###### 

###### RAM Loading (Live Mode): บูตโหลดเดอร์โหลด Kernel และถ่ายโอนระบบปฏิบัติการ Alpine ทั้งหมดขึ้นไปทำงานบนหน่วยความจำ (RAM) ชั่วคราว โดยไม่มีการเขียนข้อมูลลงฮาร์ดดิสก์เป้าหมายหากไม่ได้รับคำสั่ง

###### 

###### GUI Initialization: ระบบประมวลผลเซอร์วิส Xorg และตัดเข้าสู่หน้าจอ Desktop XFCE อัตโนมัติ พร้อมสำหรับการเสียบเมาส์และคีย์บอร์ด

###### 

###### Rescue Operations: ผู้ใช้รันเครื่องมือหรือสคริปต์เพื่อเมานต์ดิสก์เป้าหมาย -> เข้าถึงไฟล์ที่สูญหายหรือถูกล็อก -> โอนย้ายข้อมูลลง External Drive อย่างปลอดภัย

###### 

###### System Halt: ปิดเครื่อง -> ข้อมูลบน RAM จะถูกล้างออกทั้งหมดโดยไม่ทิ้งร่องรอยการทำงานในเครื่องต้นทาง





### **Main Features: Automatic Run**



#### **1.กู้คืนและสำรองข้อมูลด่วน (Data Recovery \& Backup)**

###### เข้าถึงฮาร์ดดิสก์หรือ SSD ของเครื่องที่พังเพื่อดึงข้อมูลสำคัญ (เช่น รูปภาพ เอกสารงาน) ออกมาเก็บไว้ในแฟลชไดรฟ์หรือ External Storage ใช้เครื่องมืออย่าง rsync หรือตัวจัดการไฟล์แบบ GUI เพื่อย้ายข้อมูลได้อย่างปลอดภัย



#### ! 1.1 แยกแยะ "ตัวโปรแกรมกู้ภัย" ออกจาก "พื้นที่เก็บข้อมูลที่กู้มา"

##### เข้าใจก่อนว่าแฟลชไดรฟ์ 8GB เก็บอะไร: แฟลชไดรฟ์ตัวนี้ไม่ได้เอาไว้ "เก็บไฟล์ที่กู้ทั้งหมด" ครับ แต่มันเอาไว้เก็บตัวระบบ Rescue-OS, ไฟล์ตั้งค่า (lbu), และสคริปต์เครื่องมือต่างๆ ซึ่งกินพื้นที่จริงๆ แค่ไม่กี่ร้อย MB เท่านั้น

##### 

##### ทางออกเรื่องพื้นที่น้อย: เวลาเราจะดูดข้อมูลจากเครื่องที่พัง เราจะ ไม่เซฟลงแฟลชไดรฟ์ Rescue-OS ของเรา แต่เราจะหา External Harddisk / SSD อีกลูก หรือแฟลชไดรฟ์อีกอัน มาเสียบเพิ่มเข้าไปในเครื่อง แล้วสั่งย้ายข้อมูลจากฮาร์ดดิสก์ตัวที่พัง ไปลงที่ External ตัวสำรองนั้นแทนครับ



#### ! 1.2 ใช้หลักการ "เลือกเฉพาะไฟล์ที่จำเป็น" (Selective Backup)

###### ถ้าเราไม่มี External Harddisk อีกลูก และจำเป็นต้องใช้พื้นที่จำกัดบนแฟลชไดรฟ์พกพาจริงๆ เราจะใช้วิธี คัดเลือกเฉพาะไฟล์สำคัญ (Triage \& Selective Recovery) แทนที่จะดูดมาทั้งหมด:

###### 

###### ไม่กู้: ไฟล์ระบบ Windows (C:\\Windows), ไฟล์โปรแกรมติดตั้ง (Program Files), หรือไฟล์แคชขยะ

###### 

###### เน้นกู้เฉพาะ: โฟลเดอร์งานสำคัญของผู้ใช้ เช่น Desktop, Documents, Downloads, รูปภาพ, หรือฐานข้อมูลโปรแกรม เราสามารถใช้คำสั่งอย่าง rsync ระบุเงื่อนไขให้ดูดมาเฉพาะไฟล์สกุลที่ต้องการได้ (เช่น กู้เฉพาะไฟล์ .docx, .pdf, .jpg เท่านั้น) ทำให้ใช้พื้นที่น้อยมากๆ ครับ



#### ! 1.3 การกู้ข้อมูลแบบวิเคราะห์สดโดยไม่ย้ายไฟล์ (In-Place Analysis)

###### ถ้าใช้โปรแกรมจำพวก TestDisk หรือ GParted เพื่อซ่อมแซมพาร์ทิชันที่เสียหาย (เช่น ตารางพาร์ทิชันพัง, เผลอลบพาร์ทิชันโดยไม่ได้ตั้งใจ):

###### โปรแกรมพวกนี้จะทำการ "ซ่อมโครงสร้าง" บนตัวฮาร์ดดิสก์ลูกนั้นๆ โดยตรงเลยครับ มันไม่ต้องใช้พื้นที่บนแฟลชไดรฟ์ของเราในการเก็บไฟล์จำลอง แค่ใช้ RAM ของเครื่องในการคำนวณและเขียนแก้ตารางพาร์ทิชันใหม่ให้กลับมามองเห็นได้เหมือนเดิม (ซ่อมเสร็จก็บูตวินโดวส์ติดได้เลยโดยไม่ต้องย้ายไฟล์ออกสักกิกะไบต์เดียว)



### **2.ซ่อมแซมบูตลูบและตัวจัดการการบูต (Bootloader Repair)**

##### แก้ไขปัญหาคอมพิวเตอร์ที่เปิดไม่ติด ติดวนลูปหน้าจอซ่อมแซมอัตโนมัติ (Automatic Repair) หรือไฟล์ระบบบูตหาย (เช่น ซ่อมแซม Windows Boot Manager, EFI Partition หรือ GRUB ของลินุกซ์)



##### 2.1 กรณีซ่อม Windows Boot Manager (บูตลูป, จอฟ้าหาไดรฟ์ไม่เจอ)

###### ในเมื่อระบบปฏิบัติการหลักของเราคือ Linux เราจะไม่สามารถรันคำสั่งซ่อมของ Windows (เช่น bootrec หรือ bcdboot) ได้ตรงๆ แต่เราจะใช้วิธี "เข้าไปแก้โครงสร้างไฟล์และพาร์ทิชันโดยตรง" ครับ:

###### 

###### แก้ Flag พาร์ทิชันด้วย GParted: หลายครั้งที่ Windows บูตไม่ขึ้นเพราะค่าสถานะ (Flag) ของพาร์ทิชันบูตหลุด เราแค่เปิด GParted ขึ้นมา คลิกขวาที่พาร์ทิชัน EFI ขนาด 100MB แล้วติ๊กเลือก Flag คำว่า boot และ esp ให้กลับมาทำงาน เครื่องก็จะบูตติดทันที

###### 

###### ซ่อมไฟล์ EFI ที่สูญหาย: เราสามารถใช้คำสั่งเมานต์พาร์ทิชัน EFI (FAT32) เพื่อเข้าไปดูโฟลเดอร์ EFI/Microsoft/Boot/ หากพบว่าไฟล์ระบบเช่น bootmgfw.efi เสียหายหรือโดนไวรัสลบ เราก็แค่ก๊อปปี้ไฟล์บูตมาตรฐาน (ที่เราเตรียมสำรองไว้ใน Rescue-OS) ไปวางทับแทนที่

###### 

###### สำรองข้อมูลก่อนล้างเครื่อง: ถ้าระบบบูต Windows พังหนักจนแก้โครงสร้างไฟล์ไม่หายจริงๆ Rescue-OS จะทำหน้าที่ดูดไฟล์สำคัญในไดรฟ์ C: ออกมาให้หมด ก่อนที่เราจะตัดสินใจลง Windows ใหม่ครับ

###### 

##### 2.2 กรณีซ่อม GRUB ของ Linux (ระบบบูตพัง หาเมนูบูตไม่เจอ)

###### อันนี้คือท่าไม้ตายและของถนัดของ Rescue-OS เลยครับ เราจะใช้กระบวนการ Chroot (ทะลวงระบบ) เพื่อจำลองตัวเองเข้าไปนั่งอยู่ในระบบปฏิบัติการที่พัง แล้วสั่งสร้างตัวบูตขึ้นมาใหม่:

###### 

###### Mount ทะลวงไส้: เมานต์พาร์ทิชันหลักที่พัง (เช่น /dev/sda2) เข้ามาที่โฟลเดอร์ /mnt

###### 

###### Bind Mount อุปกรณ์: ผูกระบบฮาร์ดแวร์จำลองเข้าด้วยกัน เพื่อให้สคริปต์ซ่อมทำงานได้

###### 

###### mount --bind /dev /mnt/dev

###### 

###### mount --bind /proc /mnt/proc

###### 

###### mount --bind /sys /mnt/sys

###### 

###### สั่ง Chroot: รันคำสั่ง chroot /mnt (ระบบจะสลับตัวเรา ทะลุเข้าไปอยู่ในเครื่องเป้าหมายที่พังอยู่ ราวกับว่าเรากำลังเปิดเครื่องนั้นจริงๆ)

###### 

###### ติดตั้ง GRUB ใหม่: รันคำสั่ง grub-install /dev/sda ตามด้วย update-grub เพียงเท่านี้ระบบเมนูบูตที่หายไปก็จะถูกสร้างใหม่ทั้งหมดอย่างสมบูรณ์แบบครับ



#### Windows/Linux พังแบบไหนถึงยังซ่อมได้

##### 1\. อาการพังระดับซอฟต์แวร์ (กู้ได้ 90-100%)

###### 

###### ระบบบูตพัง (Bootloader Corruption): เปิดเครื่องแล้วเจอข้อความ No Bootable Device, Operating System Not Found, หรือจอฟ้า (BSOD) ทันทีที่เปิดเครื่อง อาการนี้เกิดจากไฟล์นำบูต (EFI/BCD/GRUB) หายหรือพัง ตัวข้อมูลในไดรฟ์ C: ยังอยู่ครบ แค่ใช้ Rescue-OS เข้าไปซ่อมไฟล์บูตก็กลับมาใช้งานได้

###### 

###### ติดลูปซ่อมแซมอัตโนมัติ (Automatic Repair Loop): วินโดวส์พยายามซ่อมตัวเองแต่ไม่สำเร็จจนวนลูป อาการนี้มักเกิดจากการอัปเดตระบบผิดพลาด เราสามารถบูตผ่าน USB เข้าไปดึงข้อมูลสำคัญออกมาก่อนลง OS ใหม่ได้

###### 

###### เผลอลบไฟล์หรือฟอร์แมตผิดไดรฟ์: ตราบใดที่คุณ ยังไม่ได้เขียนข้อมูลใหม่ลงไปทับ (Overwrite) เครื่องมืออย่าง TestDisk หรือ PhotoRec ใน Rescue-OS สามารถสแกนและงัดเอาไฟล์ที่ถูกลบไปแล้วกลับมาได้แม้จะกด Shift+Delete ไปแล้วก็ตาม

###### 

###### พาร์ทิชันกลายเป็น RAW หรือ RAW Drive: เปิดไดรฟ์ไม่ได้ และระบบฟ้องว่า You need to format the disk before you can use it อาการนี้คือ "ตารางสารบัญ" ของไดรฟ์พัง (Partition Table/MFT corruption) แต่เนื้อไฟล์จริงๆ ยังอยู่ เราใช้ GParted หรือ TestDisk ซ่อมตารางสารบัญนี้ได้

###### 

###### โดนไวรัสทำลายระบบปฏิบัติการ: ไวรัสลบไฟล์ระบบจนเครื่องรันไม่ขึ้น เราสามารถใช้ Live USB เข้าไปเป็นตัวกลางในการสำรองข้อมูลออกมาได้อย่างปลอดภัย เพราะไวรัสของ Windows จะไม่สามารถรันและทำอันตรายระบบ Linux ของเราได้ (ยกเว้นกรณีโดน Ransomware ล็อกรหัสไฟล์ อันนี้ไฟล์อาจจะกู้ไม่ได้ ต้องอาศัย Key ถอดรหัสเท่านั้น)

###### 

##### 2\. อาการพังระดับฮาร์ดแวร์ (กู้ด้วยโปรแกรมไม่ได้ ต้องส่ง Lab หรือเปลี่ยนอะไหล่)

###### 

###### BIOS มองไม่เห็นฮาร์ดดิสก์/SSD เลย: ถ้าคอมพิวเตอร์และ Rescue-OS มองไม่เห็นตัวอุปกรณ์ในระดับฮาร์ดแวร์ (พิมพ์ lsblk แล้วไม่เจอตัวไดรฟ์) แปลว่าแผงวงจร (Controller) พัง ซอฟต์แวร์จะเข้าไปทำอะไรไม่ได้

###### 

###### มีเสียงดังแก๊กๆ (Click of Death): หัวอ่านฮาร์ดดิสก์แบบจานหมุนพังและกำลังขูดจานแม่เหล็ก หากเจออาการนี้ต้องรีบปิดเครื่องทันที ห้ามรันโปรแกรมกู้ข้อมูลใดๆ เพราะยิ่งรันจะยิ่งทำให้จานเป็นรอย ต้องส่งศูนย์กู้ข้อมูล (Clean Room) เท่านั้น

###### 

###### Bad Sector สาหัส: ฮาร์ดดิสก์เสื่อมสภาพอย่างหนัก อ่านข้อมูลแล้วค้างตลอดเวลา แม้ลินุกซ์จะมีคำสั่งอย่าง ddrescue ที่ช่วยพยายามดึงข้อมูลข้ามจุดที่พังได้ แต่ก็มีความเสี่ยงที่ไดรฟ์จะน็อกถาวรระหว่างกระบวนการ





### **3.GParted: จัดการพาร์ทิชันและโครงสร้างดิสก์ (Partition Management)**



###### เปิดโปรแกรมและเลือกไดรฟ์:



###### ไปที่เมนู Applications > System > GParted



###### ที่มุมขวาบนของหน้าต่าง จะมีเมนู Dropdown ให้เลือกฮาร์ดดิสก์เป้าหมาย (เช่น /dev/sda คือฮาร์ดดิสก์หลัก, /dev/sdb คือแฟลชไดรฟ์) ต้องดูขนาด (Size) ให้ชัวร์ก่อนกดสั่งงาน

###### การย่อ/ขยายพื้นที่ (Resize/Move):



###### คลิกขวาที่พาร์ทิชันที่ต้องการ > เลือก Resize/Move



###### คุณสามารถใช้เมาส์ลากแถบสไลเดอร์ซ้าย-ขวาเพื่อปรับลดหรือเพิ่มขนาดพื้นที่ได้อย่างอิสระ (เหมาะสำหรับกรณีต้องการแบ่งไดรฟ์ C: มาสร้างไดรฟ์ D: เพิ่ม)



###### การลบและการสร้างใหม่ (Delete/Create):



###### หากต้องการลบ: คลิกขวาพาร์ทิชัน > Delete (พื้นที่จะกลายเป็นก้อนสีเทา Unallocated)



###### หากต้องการสร้างใหม่: คลิกขวาที่พื้นที่สีเทา > New > เลือกชนิดระบบไฟล์ (เช่น ntfs สำหรับ Windows)



###### การซ่อมแซมพาร์ทิชัน (Rescue):



###### ถ้าไดรฟ์กลายเป็น RAW หรือเผลอลบพาร์ทิชันทิ้งไป ให้ไปที่แถบเมนูด้านบน เลือก Device > Attempt Data Rescue โปรแกรมจะสแกนหาตารางพาร์ทิชันเก่าที่ซ่อนอยู่แล้วพยายามกู้โครงสร้างกลับมาให้



###### จุดสำคัญที่ต้องระวัง: ทุกคำสั่งที่คุณกดไป (ลบ, สร้าง, ขยาย) GParted จะแค่จำไว้ชั่วคราวและยังไม่ส่งผลกระทบใดๆ กับฮาร์ดดิสก์ จนกว่าคุณจะกดยืนยันที่ปุ่ม Apply All Operations (ไอคอนเครื่องหมายถูกสีเขียวที่แถบเครื่องมือด้านบน) ระบบถึงจะเริ่มประมวลผลจริงครับ



### **4.กู้ข้อมูล**

###### กฎเหล็กก่อนเริ่มกู้ข้อมูล: คุณต้องเตรียมแฟลชไดรฟ์หรือฮาร์ดดิสก์อีกลูกมาเสียบเมานต์รอไว้ (เช่น เมานต์ไว้ที่ /mnt/usb) เพื่อใช้เป็น "ที่เซฟไฟล์ที่กู้มาได้" ห้ามเซฟไฟล์กลับลงไปในไดรฟ์ที่กำลังกู้เด็ดขาด เพราะข้อมูลใหม่จะไปเขียนทับข้อมูลเก่าที่รอการกู้ครับ นี่คือวิธีใช้งานเครื่องมือทั้ง 2 ตัวแบบแยกตามสถานการณ์ครับ:

###### 

#### 4\.1 วิธีใช้ PhotoRec (กู้ไฟล์ที่เผลอลบ / ไดรฟ์โดนฟอร์แมต)

###### ตัวนี้จะเมินตารางพาร์ทิชันที่พัง แล้ววิ่งไล่กวาดหาไฟล์ (รูปภาพ, วิดีโอ, เอกสาร) จากหน้าดิสก์ตรงๆ

###### 

###### พิมพ์คำสั่ง photorec ใน Terminal แล้วกด Enter

###### 

###### เลือกไดรฟ์: เลื่อนลูกศรเลือกฮาร์ดดิสก์ตัวที่ข้อมูลหาย แล้วกด \[Proceed]

###### 

###### เลือกพาร์ทิชัน: เลือกพาร์ทิชันที่ต้องการกู้ หรือถ้าพังทั้งลูกให้เลือก \[Whole disk] แล้วกด \[Search]

###### 

###### เลือกระบบไฟล์:

###### 

###### หากกู้ไฟล์จาก Windows (NTFS, FAT32) ให้เลือก \[Other]

###### 

###### หากกู้จาก Linux ให้เลือก \[ext2/ext3]

###### 

###### เลือกพื้นที่สแกน: เลือก \[Free] (สแกนเฉพาะพื้นที่ว่างที่ไฟล์โดนลบ) หรือ \[Whole] (สแกนทั้งไดรฟ์กรณีโดนฟอร์แมต)

###### 

###### เลือกที่เก็บไฟล์กู้คืน (สำคัญ): ระบบจะให้คุณเลือกโฟลเดอร์ปลายทาง (เช่น /mnt/usb) เมื่อเข้าไปในโฟลเดอร์ที่ต้องการแล้ว ให้กดปุ่ม C บนคีย์บอร์ด เพื่อยืนยัน

###### 

###### โปรแกรมจะเริ่มสแกนและดึงไฟล์ออกมาเซฟในโฟลเดอร์ปลายทางให้ทันที (ไฟล์ที่ได้จะถูกตั้งชื่อใหม่รันตามตัวเลข ซึ่งเราต้องไปเปิดดูและจัดเรียงเองภายหลัง)

###### 

#### 4\.2 วิธีใช้ TestDisk (กู้พาร์ทิชันทั้งก้อนที่เผลอลบ หรือซ่อมไดรฟ์ RAW)

###### ตัวนี้ไม่ได้กู้เป็นรายไฟล์ แต่จะหา "ตารางสารบัญ" ที่โดนลบไปแล้วเขียนกลับคืนมา ทำให้ไดรฟ์กลับมาเปิดได้เหมือนเดิมโดยไฟล์ทุกอย่างอยู่ครบและชื่อไม่เปลี่ยน

###### 

###### พิมพ์คำสั่ง testdisk ใน Terminal แล้วกด Enter

###### 

###### เลือก \[Create] เพื่อสร้างไฟล์เก็บ Log การทำงาน

###### 

###### เลือกไดรฟ์: เลื่อนลูกศรเลือกฮาร์ดดิสก์ตัวที่มีปัญหา แล้วกด \[Proceed]

###### 

###### เลือกชนิดตาราง (Partition Table): ปกติระบบจะตรวจจับให้เอง (มักจะเป็น \[Intel] สำหรับคอมเก่า หรือ \[EFI GPT] สำหรับคอมปัจจุบัน) กด Enter ได้เลย

###### 

###### เลือก \[Analyze] ตามด้วย \[Quick Search] เพื่อให้ระบบสแกนหาโครงสร้างพาร์ทิชันเดิมที่ซ่อนอยู่

###### 

###### ระบบจะแสดงรายชื่อพาร์ทิชันที่ค้นพบ (ตัวอักษรสีเขียว)

###### 

###### คุณสามารถกดปุ่ม P เพื่อพรีวิวดูรายชื่อไฟล์ข้างในได้ว่าใช่พาร์ทิชันที่ต้องการไหม (กด Q เพื่อออกจากการพรีวิว)

###### 

###### หากเจอพาร์ทิชันที่ถูกต้อง ให้กด Enter เพื่อตกลง

###### 

###### เลื่อนลูกศรไปที่ปุ่ม \[Write] แล้วกด Enter เพื่อเขียนตารางสารบัญใหม่ลงไปในฮาร์ดดิสก์ (กดยืนยัน Y)

###### 

###### รีบูตเครื่อง 1 ครั้ง ไดรฟ์ที่เคยมองไม่เห็นก็จะกลับมาใช้งานได้ตามปกติครับ

###### 

###### ทั้งสองตัวนี้คือเครื่องมือที่ร้านกู้ข้อมูลและผู้ดูแลระบบใช้กันเป็นมาตรฐานเลยครับ



### **5.ตรวจสอบสุขภาพฮาร์ดแวร์และไวรัส (Diagnostic \& Antivirus)**

###### ขั้นตอนนี้แอบเป็น "จุดชี้เป็นชี้ตาย" ของการกู้ข้อมูลเลย ช่างคอมระดับโปรจะทำขั้นตอนนี้ "ก่อน" เริ่มกู้ไฟล์เสมอครับ เพราะถ้าฮาร์ดดิสก์กำลังจะพัง (หัวอ่านใกล้ขิต) การฝืนสั่งก๊อปปี้ไฟล์หนักๆ อาจทำให้ไดรฟ์พังถาวรคามือได้เลย ใน Rescue-OS ของเราสามารถจัดการ 2 เรื่องนี้ได้เด็ดขาดมากครับ:



#### 1\. เช็กสุขภาพฮาร์ดดิสก์ด้วย S.M.A.R.T. (ป้องกันไดรฟ์พังคามือ)

###### ในตัวฮาร์ดดิสก์และ SSD ทุกลูกจะมีระบบหมอประจำตัวที่เรียกว่า S.M.A.R.T. คอยจดบันทึกอาการป่วยเอาไว้ เราสามารถใช้ Linux เข้าไปดึงประวัติการป่วยนี้มาดูได้ครับ

###### 

###### เครื่องมือที่ใช้: smartmontools (ติดตั้งด้วยคำสั่ง apk add smartmontools)

###### 

###### วิธีใช้งาน: พิมพ์คำสั่ง smartctl -a /dev/sda (เปลี่ยน sda เป็นชื่อไดรฟ์เป้าหมาย)

###### 

###### สิ่งที่ระบบจะบอกเรา: มันจะสรุปผลบรรทัดเดียวเลยว่าสุขภาพโดยรวมคือ PASSED (ปกติ ลุยต่อได้) หรือ FAILED (กำลังจะพัง!) และจะบอกด้วยว่ามี Bad Sector (จุดที่ข้อมูลพัง) เยอะแค่ไหน ถ้าเห็นว่า FAILED เราจะได้ระวังตัว ไม่สั่งรันสแกนอะไรหนักๆ แต่จะรีบดูดเฉพาะไฟล์ที่สำคัญที่สุดออกมาก่อน

###### 

### 2\. สแกนกำจัดไวรัส (จับตายมัลแวร์ตอนมันกำลังหลับ)

###### เวลาคอมพิวเตอร์โดนไวรัสเล่นงานจนบูต Windows ไม่ขึ้น ถ้าเราเอาแฟลชไดรฟ์ Rescue-OS ของเราไปเสียบ มันจะมีความได้เปรียบระดับโกงอยู่ข้อหนึ่งครับ คือ "ไวรัสของ Windows ไม่สามารถรันบน Linux ได้"

###### 

###### เครื่องมือที่ใช้: clamav (โปรแกรมแอนตี้ไวรัสโอเพนซอร์สยอดฮิตบนลินุกซ์)

###### 

###### วิธีใช้งาน: เราแค่ใช้สคริปต์ auto-mount.sh เมานต์ไดรฟ์ Windows ขึ้นมา จากนั้นพิมพ์คำสั่ง clamscan -r --remove /mnt/sda1

###### 

###### ผลลัพธ์: ตัวแอนตี้ไวรัสบน Linux จะเดินไล่สแกนโฟลเดอร์ใน Windows แล้วจับลบไฟล์ .exe ที่เป็นไวรัสทิ้งได้สบายๆ โดยที่ตัวไวรัสไม่มีสิทธิ์ฝืนหรือต่อต้านใดๆ เพราะมันอยู่ในสถานะ "หลับ" (ไม่ได้ถูกโหลดเข้า RAM) พอลบเสร็จปุ๊บ เครื่องก็กลับมาบูตเข้า Windows ได้ตามปกติครับ
